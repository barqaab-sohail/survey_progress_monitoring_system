## Production header check

Read-only checks on 19 October found `/api/v1/health` responding with HTTP 200
JSON. `/api/v1/field/bootstrap` returned HTTP 401 `Sign in again to synchronize.`
both without Authorization and with a dummy 128-character bearer token. Against
the current middleware, a received but unknown token should instead produce
`This device session has expired or was revoked.` This strongly indicates the
header is not reaching the middleware, assuming the deployed middleware matches
the source. This is separate from invalid email/password validation at login.

The production `.htaccess` supplied by the user lacks the `CGIPassAuth On` and
`SetEnvIfNoCase Authorization` directives already present in `public/.htaccess`.
Add the following above its rewrite block, retaining hosting-managed settings:

```apache
CGIPassAuth On

<IfModule mod_setenvif.c>
    SetEnvIfNoCase Authorization "^(.+)$" HTTP_AUTHORIZATION=$1
</IfModule>
```

Retain the existing Authorization RewriteRule. The hosting provider must permit
these directives; if Apache returns HTTP 500 after this change, restore the
backup and ask the host to enable authorization-header forwarding in its
CGI/FastCGI configuration. Do not work around this by weakening token checks.

After deployment, repeat the dummy-token check. Its expected response is still
HTTP 401, but with `This device session has expired or was revoked.` Then test a
real sign-in and assignment download on the phone. No APK update is needed for
this server configuration correction. No production files were changed here.

The error responses also exposed exception traces and server paths. Set
`APP_DEBUG=false` in production and refresh the configuration cache after
deploying the server configuration.
