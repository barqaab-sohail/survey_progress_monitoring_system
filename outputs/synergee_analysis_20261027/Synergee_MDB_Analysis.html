What is entered in the SynerGEE files, and why?

File summaryMain valuesLoad interpretationItems to reviewAll field meaningsSources and method

These files contain electrical network model inputs: feeder source settings, transformer references, network sections, per-phase load allocations and map coordinates. They are not tables of solved voltage drop, losses, current or measured transformer utilization.

The complete Excel reference contains all 13,180 stored field values from 475 records, with source file, table, record identifier, field name, units, short meaning and interpretation notes. The dictionary below explains all 257 table-specific fields across nine populated tables. Each database has the same 50-table schema: seven tables are populated in every file; three Jodh Pur files also have distributed-generation and year-specific generation records. Forty-one tables are empty in all seven files. Empty tables mean no records were supplied there; they do not prove those devices are absent in the physical network.

3. How to understand the load entries

kW is real power, kvar is reactive power, kVA is apparent power or a connected-capacity basis, and kWh is energy over a period. They serve different purposes and cannot be substituted for one another. ArcFM documentation specifically describes connected kVA as a basis from which SynerGEE can allocate feeder loads [S1].

Across all 137 load records, all 411 kW phase cells and all 411 kvar phase cells are numeric zero. All 411 kWh phase cells are NULL. Nonzero quantities are entered in the customer and kVA fields. The selected allocation method, customer-class definitions, equipment database and study settings are therefore needed to establish how these inputs become an actual solved load. No peak demand, losses, power factor, voltage drop or transformer loading percentage has been inferred from these entries.

4. Findings that matter when using the model

  1. Frequency: all seven files contain Frequency=60 Hz. The cited Pakistan distribution code uses a 50 Hz nominal basis [S3]. Review the intended model frequency before relying on results; no source values have been changed.
  2. Connected kVA is not peak demand: for example, T-3030216724 has a 200 KVA type label and an entered kVA sum of 518. Dividing them does not establish 259% operating loading. Load allocation/diversity and solved demand are required.
  3. Equipment library missing: transformer and conductor names are references. Exact transformer voltage ratio, impedance, winding vector group, conductor size/material, ampacity and electrical constants are not fully specified by these network files [S2].
  4. Meter records are placeholders: each file has one InstMeterPoints row, but only SectionId is populated. All 33 other fields are NULL; there are no supplied meter readings or meter demand targets.
  5. Source fault impedances are zero: all four source sequence-impedance fields are zero. This is not a verified utility short-circuit equivalent and limits interpretation of fault-study inputs.
  6. Physical transformer voltages remain unresolved: SpecNomKv=4.16 occurs in every transformer record, together with NomKvMode=C. Its active meaning is unverified. PTSecondary=120 and LTC targets of 122 are control-related values, not proof of LV system voltage.
  7. Geometry values need their proper scales: all 130 Secondary Distribution section lengths exactly match straight-line distances between stored X/Y endpoints. This supports metre-based, coordinate-derived lengths; it does not establish surveyed routed conductor length. The 121.9/91.4 spacing values must not be treated as metres without checking the geometry unit convention.
  8. Leading spaces in library references: every PhaseConductor2Id has a leading space, including space-only references on absent phases. Preserve them in an audit. Check whether library lookup trims whitespace before changing anything.
  9. Phase completeness checked: no active phase has a blank conductor key, NULL customers or NULL kVA, and no nonzero kVA occurs on a phase absent from its section. Blank phase entries in these files therefore should not automatically be classified as missing active-phase data.
  10. Topology checked: every section endpoint, load reference, meter reference and transformer section reference exists. Section and node identifiers are unique within their tables. Each file also contains one unconnected node with the bare transformer number; the .1 and .2 nodes are used by the network. This extra node is recorded for review, not assumed to be an electrical break.
  11. Repeated settings are not evidence of measured data: identical ZIP percentages, 2% growth, 6-hour repair times, 5000 cost units and tap-control settings may come from common modeling defaults. The records do not establish who measured or approved these values.
  12. Year labels and CRS declaration: 2015–2025 are slot labels; only generation has year-specific records, all at slot 0. WGS 1984 UTM Zone 43N is the declared projection, while ProjectionWKT is empty. Confirm the zone against the actual survey before mapping; this review did not geolocate or validate the coordinate system.

7. Sources, extraction and limits

All supplied databases were opened read-only using Microsoft ACE OLE DB. All rows and columns in all 50 ordinary user tables were read. Source SHA-256 hashes were checked before and after extraction and were unchanged. The extraction covers stored table data; it does not execute Access macros, queries or any text instructions inside records, and it does not run the SynerGEE solver. No instructions embedded in data were treated as user instructions.

The user describes these files as approved. This report explains their stored contents; it does not independently establish an approval workflow or an engineering certification. The blank LastSavedBy/LastSavedDate fields do not identify the approving person or date.
